# Contract change proposals — WP11

## 2026-09-25 — Bloom intensity calibration (spec tuning, no code contract change)
- **WP:** WP11
- **Change:** `BloomEffect.intensity = atm.bloomIntensity * POST_TUNING.BLOOM_SCALE` with `BLOOM_SCALE = 0.12`
  (src/post/PostStack.ts). DESIGN §WP11 PostStack step 4 reads `intensity: atm.bloomIntensity`. The atmosphere
  table values (0.4-0.6) are unchanged; only the mapping to pmndrs' `intensity` is scaled.
- **Rationale:** the bloom input is the un-exposed HDR buffer in absolute nits with threshold `1/exposure`. The
  mipmap-blur upsample chain sums every level, so at `intensity = 0.5` a 3300-nit troffer adds a halo that washes
  over the whole ceiling. The harness (`harness/post.html?scene=panels`) was calibrated at x0.12: ring luma
  around the panels goes from 0.37 without bloom to 0.44 with it (a visible camcorder glow), and 0 % of the
  pixels outside the panels clip. The atmosphere table therefore still reads as relative bloom strength per zone.
- **Consumers affected:** none (internal to WP11). Proposed DESIGN edit: "intensity: atm.bloomIntensity x 0.12
  (calibration of the table value to pmndrs' mip-chain gain)".

## 2026-09-25 — setExposureLock semantics (clarification, no signature change)
- **WP:** WP11
- **Change:** `setExposureLock(ev)` pins EV100 only. The exposure formula is unchanged:
  `exposure = 1/(1.2 * 2^(EV100 - atm.exposureBias - settings.brightnessEV))`. The zone's look offset and the
  user's brightness therefore apply under a lock exactly as they do under auto-exposure.
  `PostStack.exposure.ev100` reports the locked EV.
- **Rationale:** DESIGN says only "pins it". With this reading, locked and auto shots of a zone share the same
  grade/offset.
- **Consumers affected:** WP14 (`exposure=` launch param, `setExposure` debug call). No code change is needed.
